# 产品需求

## 0.2.2 用户明确调整

- B 失败回退 A 原文后提供手动重试入口，只重新调用 B，不重复 A 的分析与工具工作。
- 成功初稿/核对可在材料、模型和指令一致时复用；用户可先调整设置再重试。

## 0.2.1 用户明确调整

- 起草和核对阶段原本写在代码中的完整提示词可在插件设置中修改，方便用户自行调整。
- 默认预填当前全文；用户保存后直接用于对应阶段。保留表达偏好、恢复默认和后续回复生效的设置语义。

## 0.2.0 用户明确调整（优先于下方早期建议范围）

- A 负责分析与执行；B 从 A 本次成稿之前的工作上下文独立写报告，不以 A 成稿为起草输入。
- 暂不要求在 A 写报告前中断。A 正常完成后，B 使用预先捕获的上下文，第一步排除 A 这次成稿。
- B 第二步才获得 A 报告，用于查漏纠错；必须在自己的初稿上完善，保持自己的结构和表达，不能改成润色 A 报告。
- 支持两步或多步调用：独立起草一次，默认核对一次，核对轮数由用户设置，可设 0。
- 尽量减少 A 的文风影响：不传 A 系统文风、隐藏推理和 provider replay；已显示的历史回复优先用 B 版本。
- 输入、输出和等待时间由用户控制，不设旧版低上限或隐藏输出字符限制；0 表示插件不额外限制/输出跟随模型。
- A 原始记录保留。未完成核对的 B 初稿不直接展示；失败回退 A，取消停止后续调用。多步请求和用量独立记录。

事实核对只能提供模型层面的纠错，不能声称自动证明事实正确。不能把隐藏内部状态当作可完整移交的上下文。

## 建议的第一版范围（0.1.x 历史设计）

- 选择器以 `provider + model` 精确匹配，允许多个 A 映射到一个 B；默认不使用模糊显示名或通配符。
- 匹配当前实际模型调用，不依赖会话最初的默认模型。中途切到 C 后必须直通。
- 处理主聊天中可见的、成功正常结束、没有工具调用的非空助手文本。不是只处理“整个任务完成”的一个节点。
- 带工具调用的同次回复全部直通，文本前置、后置、交错都不改写。若 A 把进度文本单独正常结束后才在另一次请求调用工具，第一版可能把该条当候选；不做无法可靠预测未来的判断。
- 不按字数独断跳过：一句很短的关键问题也属于交流。暂不增加额外分类模型。
- 推理内容、工具参数、代码文件、工具结果、内部摘要、会话标题、agent 内部转发不交给 B 改写。
- 非文本附件保留；结构化机器输出、纯代码产物优先跳过或按明确规则保留，不能擅自改成散文。
- B 不获得工具权限，也不读取 A 的完整隐藏推理。提供 A 原文、用户相关问题和最小必要的公开对话上下文。
- 单一聊天回复默认展示 B 版本，原文可展开。不能先完整展示 A 原文，随后闪烁替换为 B。
- B 失败或质量检查不通过时回退 A 原文；不得要求 A 重新完成工作。

上述为可执行的建议范围，不是用户已经逐项指定的 UI 和实现细节。若宿主机制不满足，应记录差异而非悄悄缩减。

## B 的质量要求

- 保留事实、否定、限定条件、执行状态和不确定性。
- 保留数字、路径、命令、代码块、链接目标和引用对应关系；可以调整周围说明。
- 不补充未经 A 支持的结论、工作成果或承诺，不把“尚未验证”改成“已验证”。
- 问题仍然是问题；备选项的含义、顺序和编号保持稳定，便于用户说“选第二项”。
- 允许重组段落和解释原文中的术语，但不能删除影响决定的重要条件。
- 自动检查只能发现一部分改写错误，不能宣称语义等价已得到完全保证。

## 第一版之外

- B 控制工具、规划任务、执行文件操作或充当 supervisor。
- 所有模型的强制统一文风。
- 直接修改 DSH 安装包、私有 Electron 注入或 DOM 文本替换。
- 自动改写 ask-user 工具表单、审批文本或机器可读协议。
- 默认重写既有历史会话；回放只使用已经保存的改写结果，不重复计费。
- 默认影响 CLI、SDK、导出和所有第三方客户端。扩展到这些面需另外设计和测试。

## 用户体验验收

用户发送任务后，A 按原方式工作；工具过程正常出现。A 输出符合条件的报告时，界面显示整理中状态并最终显示 B 的清晰版本。用户可以继续讨论，A 保持工作主体且能理解用户对实际显示内容的引用。切换 C 后恢复 C 自己的发言。
