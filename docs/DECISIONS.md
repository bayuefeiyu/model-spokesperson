# 实现决策

## D001 独立开发（2026-10-27，已采用）

安装目录只读；源码、依赖、测试 runtime 和用户数据均在本项目。用户本次已要求开发，授权范围涵盖本地实现与隔离验证，不包括日常桌面安装。

## D002 Host + Client 展示稿（2026-10-27，已验证）

保留 A 原始日志；B 为独立插件记录，Client 在原助手行显示。真实 AgentLoop 测试验证工具和 replayState 不变，浏览器验证 pending/替换/原文/刷新。未选择流替换，因为它混淆原始 provider 内容与元数据。

## D003 正式日志和 projection（2026-10-27，已采用）

用实验 appendPluginRecord 记录，用 sessionProjections 增量折叠。下次用户输入经 pre-step decision.messages 注入可回放 notice，无额外自动 turn。固定 rc.3 并保留实验性兼容边界，不使用弃用同步扫描接口。

## D004 默认 renderer 包装（2026-10-27，已验证）

使用公开 slot 注册表和原组件，保留 locale/inject，不复写 Markdown。实际打包 registrant 压缩为 Gb，改以公开子槽声明识别默认项。子槽声明不能重复，用私有别名镜像叶子组件和授权 renderSlot。Service 方法保留 receiver；真实 SlotCore 测试覆盖声明、委托和卸载。

## D005 安装包与模块身份（2026-10-27，已验证）

bundle 内携带两个实现包，patch 使用相对入口。开发 root 不设 npm workspaces，防 installation-first 选择开发链接。隔离 home 位于 runtime 下面，共享 DSH 模块；此前跨副本调用 Session 私有方法失败证明不能混用。保留 peer/engine 检查，不用强制安装绕过兼容。

## D006 恢复与回退（2026-10-27，已采用）

验证稿先 flush 再 ready。重启不请求历史 B；未完成记录恢复已验证暂存稿或回退。过期/取消结果不提交，失败不重做 A，provider 异常详情不入记录。精确关键片段规则保守拦截，但不声称证明自然语言等义。

## D007 仓库根与 tarball 共用组合包（2026-10-28，已采用）

0.1.0 仅 staging tarball 有组合包声明，GitHub URL 读取的开发根清单没有，导致插件管理器拒绝。0.1.1 将唯一组合包清单与 patch 提升到仓库根，提交预构建文件，直接从根打包，不依赖安装时执行构建。增加官方 patch 解析回归及 GitHub URL 实装验证；原 tarball 验收不能代替仓库 URL 验收。

## D008 原生插件详情配置（2026-10-28，已采用）

使用 plugins.bundle.config、ConfigForm 和 volatile Config 接口，不实现自定义远程设置协议或浏览器副本。设置有 revision 冲突保护；只有保存才写 profile。A/B 从宿主模型目录选择，仍以实际 provider/model 匹配。每次 attempt 固定一份设置快照，新设置作用于后续回复，避免更新文风或路由改变进行中任务。

## D009 独立起草与逐轮核对（2026-10-28，用户明确要求，已采用）

0.2.0 用 A attempt start 时的有效工作快照起草，B 第一步排除 A 本次报告，后续才引入 sourceReport。每次核对以自己的 ownDraft 为唯一底稿，并重用同一份证据材料。默认一轮核对，允许 0 或多轮，不增加 A 的交接工具，也不试图预测 A 何时将从分析转为报告。A 原始日志保持原样，B 仍只作答、不调用工具。

去掉对新稿的数字/代码出现次数及顺序相等要求，避免独立结构被退回 A 原文；事实忠实度依靠核对提示与工作证据，不能证明正确。保留旧规则仅恢复 v1 历史。所有阶段请求/结果/usage 随会话保存，wire 不传完整工作材料，只有全部阶段结束才公开最终稿。核对失败仍回退 A，不把初稿冒充已核对结果。

用户明确要求控制预算，因此输入/输出不设旧低上限，默认 0 表示插件不额外限制/输出跟随模型；去掉隐含输出字符限制，等待超时同样可设 0。保留已有显式限额，避免未经用户操作改变预算。浏览器和自动测试使用 mock，不把协议行为验证当作真实模型写作质量证明。

## D010 完整阶段提示词作为原生设置（2026-10-28，用户明确要求）

draftPrompt/reviewPrompt 各自保存完整提示词，包含此前共用的 COMMON 内容，用户修改后不再隐式补回默认段落。保留独立 style 并明确告知末尾附加方式。未设置字段时用当前默认值，以兼容旧 profile；恢复默认把当前版本全文作为草稿，用户保存后才写入。两字段都使用现有 volatile Config 与 ConfigForm，不增加文件编辑器或外置配置。只拒绝空白，保留有效文本原样、换行与长度；每次 attempt 的配置快照覆盖整条多轮流程。
