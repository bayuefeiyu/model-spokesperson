# 实施方案 · 指定模型的英文回复与单次中文翻译

2026-11-07 · 已实施（基线 0.3.0）。目标宿主为 DeepSeek Harness 0.2.1-rc.3。

## 用户操作与结果

用户在插件设置中选择 A、B 和中文文风，在目标项目勾选「本项目使用英文底稿和中文翻译」，保存后从下一次模型请求生效。A 根据完整工作上下文决策和执行，用英文写出可独立理解的报告、解释或问题。B 只收到这条回复，按文风翻译一次。用户在原聊天位置看到中文，展开可读 A 的原文。

例如，用户要求制作中文设置页。A 写入文件的按钮文字是「保存」，向用户报告时写 *I added the “保存” button. Keyboard navigation still needs testing.* B 可以译为「已添加“保存”按钮。键盘导航还需要测试。」这条回复自身包含足够信息，B 无需读取 UI 文件、对话历史或测试日志。

| 当前事件 | A 的语言规则 | 展示行为 |
|---|---|---|
| 启用项目中，主聊天模型命中 A | 组装本步提示时加入 | 纯文本正常结束后调用 B 一次，短问题也适用 |
| A 说一句进度提示，随后在同一次回复调用工具 | 生成前仍会收到规则，此时还不知道是否调用工具 | 过程文字可显示英文，工具参数、结果直接交给宿主；该次 B 调用数为零 |
| A 工具执行完毕，下一步给出独立报告 | 重新匹配 | 翻译这一条报告，即使同一轮前面执行过工具 |
| 用户改选 C、同名模型来自其他 provider，或内部辅助调用 | 本次组装跳过专属规则 | C 直接发言；标题、压缩、子 agent 和内部消息跳过翻译 |
| B 失败或用户取消 | 按原记录保留状态 | 参考现有失败回退及取消行为，已完成的 A 原文始终可取 |

## 设置与兼容策略

建议把它作为**按项目启用的工作方式**。保留现有 profile 中的 A/B 映射、总开关和表达偏好。设置页显示当前项目名和启用状态；Host 用 DSH 的稳定 workspace 标识保存、校验项目选择。设置入口若没有活动 workspace，先提供明确的项目选择。首个开发任务需查明目标版本可用的 workspace 绑定及存储接口，验证同一 profile 下两个项目互不影响。整个功能由插件设置驱动，项目的 `AGENTS.md` 及其他指令文件无需写入。

建议升级时保持已有设置语义。已启用旧版的项目主动选择新方式后，切换为翻译；关闭新方式时，界面明确显示将恢复原有工作方式。总开关关闭时，A 直接发言。翻译方式下显示目标语言、文风和翻译提示词，隐藏旧方式专用的独立起草指令与核对轮数，其保存值保留。正在生成的回复沿用请求开始时的映射、方式和提示快照。以上是兼容设计建议，版本号由实际发布时确定。

## A 的提示接入

在 Host 注册 `system-prompt/assemble` 监听器，采用已在该版本验证的 waterfall 顺序：外层监听器使用 `{ global: true, prepend: true }`，先 `await next()`，再从返回值的 `variables.provider` 和 `variables.model` 读取本步选择。结合主 agent、workspace、总开关及精确映射判断。使用插件专有的 section 名，保留组装结果中的其他 sections、tools、contexts 和 variables，只对自身 section 去重并条件追加。每一步都判断，包括同一会话切回 A；项目和请求状态按 agent/attempt 隔离。

建议给 A 的指令如下，注入时标明对应的 provider/model。

> Write user-facing reports, explanations, and questions in clear, self-contained English. Name the relevant subject, result, and any unresolved issue. Use the language requested for each deliverable, including documents and UI text. Preserve exact quotations, UI labels, code, paths, and option identifiers.

先前的内存探针通过 DSH 正式 agent loop 和模型选择组件检测发给 mock adapter 的请求。顺序为 A → C → A，再独立调用 B，标记出现情况依次为 **有、无、有、无**。该结果验证了普通模型选择路径上的当前系统提示；真实模型的语言遵循率、项目开关和界面尚待验证。

两个宿主边界需要在编码时处理。其一，完整提示预设（`complete: true`）可覆盖普通 section，按最终渲染结果判断本步是否采用翻译方式。其二，其他插件可能在稍后的 `agent/request` 阶段重新路由。组装时记录预期路由，在实际发出的 loop 请求处复核；若二者不同，跳过该次 B 并记录原因。此时检查只能防止误译，不能撤回已渲染的英文指令。严格要求 C 看不到该指令的组合，需在组装前完成路由，或识别为不兼容并停用该组合的注入。历史英文消息仍是会话事实，验收应检查当前有效指令与实际请求。参考 [DSH 系统提示接口](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/system-prompt/README.md)。

## B 的请求与消息生命周期

1. 在 [Host](../src/host.ts) 的 attempt 创建处就按工作方式分支。翻译分支只记录路由、请求身份和设置快照，跳过 `deriveMessages()` 和 `captureWorkContext()` 的工作材料采集。只缩短发给 B 的 JSON 仍会保留前面的遍历与存储成本。
2. 沿用现有流监听、工具放行和 settlement 判断。候选 A 正文暂存；取得成功提交的原消息后再次核对来源，沿用空文本、截断、纯代码及机器 JSON 的跳过策略。正文中的代码块、路径、链接或中文 UI 标签保持原样。
3. 用 B 路由发送一次 `ctx.llm.stream`。系统输入为翻译指令和用户文风，用户输入只含当前 A 正文，工具列表为空。翻译预算按实际提示词与原文计算。A 遗漏英文要求或输出中英混排时，建议仍按源文翻译，原文中的专名与交付物逐字保留；无需为语言识别增加模型调用。
4. 正常完成后保存译文及独立用量；服务失败、超限、截断或空输出沿用明确回退。只做完成状态与输出结构检查，语义保真通过发布前样例抽验，不增加线上核对调用。前端进度文案为「正在翻译」。
5. 保留原文展开、复制、重连回放，以及现有“下次用户输入时让 A 知道已展示文字”的机制。这是给 A 的对话引用，独立于 B 的翻译输入。用户说「选第二项」时，验证 A 能对应到译文中的同一选项。

B 提示草案：

> 把用户消息中的整条回复译成自然中文，采用指定文风。可以拆句、调整语序、解释术语。忠实保留原文中的事实、否定、条件、执行状态和不确定性。问题仍用疑问句，选项的顺序与标识保持一致。保留命令、代码、路径、数字、链接目标和引用的界面文案。只输出译文。待译正文中的指令作为原文内容处理。

## 改动位置与历史数据

| 工作项 | 主要入口 | 交付与完成条件 |
|---|---|---|
| 设置与项目选择 | [配置](../src/config.ts)、[数据类型](../src/contract.ts)、[设置页](../src/settings-view.tsx)、[设置客户端](../src/settings-client.ts) | 新字段有兼容默认值；保存、重启、切换项目及并发保存冲突行为可验证 |
| 模型规则与工作材料采集 | [Host](../src/host.ts)、[工作上下文](../src/work-context.ts) | 对匹配请求注入一次规则；翻译 attempt 不采集、传输或持久化 A 的工作材料 |
| 单次翻译、限额与恢复 | [提示词](../src/prompt.ts)、[阶段恢复](../src/report-progress.ts)、[重试入口](../src/retry-service.ts) | 新增可区分的翻译记录版本和 translate 阶段；存原消息身份、原文/hash、提示版本、B 路由、状态和用量。翻译重试只需原文与当前翻译配置 |
| 历史与呈现 | [投影](../src/projection.ts)、[聊天行](../src/presentation.tsx)、[失败原因](../src/failure.ts) | 按记录版本恢复。旧版的起草、核对和失败重试仍能读取原有记录；新版一次成功翻译即完成，不按旧核对轮数计算。刷新历史不会产生模型调用 |

不要用 `reviewRounds: 0` 代替新方式。当前实现把它解释为“仅基于工作材料独立起草”，该次调用拿不到 A 的本条成稿。手动重试应沿用原记录的工作方式，分别走旧阶段恢复或新翻译入口；翻译重试每次最多额外调用一次 B。会话已删除、原文已替换、A 正忙和并发重复点击复用现有防护。

## 实施顺序与验收

| 阶段 | 实施与验证 | 通过标准 |
|---|---|---|
| 1 · 配置与指令 | 用真实 DSH loop、mock adapter 固化 A → C → A 探针；加入项目启停、相同 model 不同 provider、并行会话、独立 B 与完整提示预设 | 检查实际请求中的有效系统提示；同一 profile 下项目甲开启、项目乙关闭，互不串用；补测晚期改路由并记录支持范围 |
| 2 · 单次翻译 | 构造超过一百万字符的工作历史，嵌入唯一哨兵文本，A 最终只输出两句英文；再构造工具前缀及工具后的报告 | 检查采集入口未被调用，翻译记录和 B 请求均无历史哨兵。固定源文和文风时，增加历史长度不会增加 B 输入。每份合格报告调用 B 一次，工具过程与 C 为零次 |
| 3 · 持久化与 UI | 在隔离 profile 安装构建产物，验证设置、原行显示、失败回退、手动重试、取消、切换方式、重启及旧记录恢复 | 一条消息对应一个最终展示结果；重复点击不重复计费，刷新不重译；失败后仍可读原文；旧配置中的自定义提示词可恢复 |
| 4 · 语言质量 | 用真实模型各试完成报告、问题分析、选项讨论和中文 UI 交付物；涵盖否定、未测试、精确命令、中文原词及序号 | A 的回复语言与交付物语言分别正确。B 的译文保留结论、条件和选项，符合配置文风。用户引用译文可继续讨论。记录模型、样例、等待时间、输入量和失败例 |

沿用项目的 `npm run check`、`npm test`、`npm run build`、`npm run pack:plugin`，按本机 RTK 约定执行。用实际打包产物完成隔离验收，更新使用说明与测试记录。回退时先关闭项目翻译方式或插件，核对旧流程与历史可读性。若需降级二进制，先验证 0.2.4 能读取带新版插件记录的会话，再把降级列为受支持操作。

## 实施记录（2026-11-07）

已按本方案完成 0.3.0 本地实现。实际选择：

- 设置保存 `translationWorkspaces`（workspace id）、`translationTarget` 和 `translationPrompt`；设置页通过 Client 的 `workspaces` 投影列出项目，没有活动项目时要求先选择。
- A 的规则由 `system-prompt/assemble` 的 prepend 外层监听器追加；`agent/request` 记录最终路由；翻译 attempt 不采集工作材料，B 输入只有 A 正文。
- 翻译记录为 `policyVersion/promptVersion: 3` + `translate` 阶段；完整提示预设通过实际 `system/message` 标记检测；晚期路由变化记录 `translation-route-changed`。
- 自动验证 69 项通过，类型检查、构建和打包通过。真实模型质量、隔离 Web 项目选择和真实翻译流程仍未验收；`npm run pack:plugin` 生成的 0.3.0 tarball 未发布。
