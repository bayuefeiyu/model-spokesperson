# 验收矩阵

先使用可重复的 mock 流与保存的 fixture；通过后才做小规模真实 API 验收。下表为验收要求，实际通过和未覆盖范围见 [验收记录](../evidence/validation.md)，不能把矩阵本身视为全部通过。

| ID | 场景 | 预期 |
|---|---|---|
| T01 | A 纯文本正常 stop | 默认 B 起草一次并核对一次；聊天主正文为最终 B，原文可读 |
| T02 | A 文本后工具调用 | 本次不调用 B；工具参数、顺序、结果与基线相同 |
| T03 | 同次多个文本/推理/工具块交错 | 不误判为独立报告，不改写工具或推理 |
| T04 | 工具执行后下一次 A 输出报告 | 报告调用 B；不能因 turn 曾有工具而跳过 |
| T05 | C 纯文本 | 不调用 B、不延迟或修改 C 的流 |
| T06 | 同名模型、不同 provider | 仅精确配置项匹配 |
| T07 | 会话 A → C → A | 每次按实际模型判断；并行会话互不影响 |
| T08 | 标题、压缩摘要、内部 agent 消息 | 不调用 B，即使使用同一 A |
| T09 | B 也使用 A 同款模型/路由 | 不递归；以调用身份而非模型名防重入 |
| T10 | 独立短问题“选方案一还是二？” | 仍属讨论候选，不能用长度阈值误跳过 |
| T11 | A aborted/error/max-tokens/空文本 | 保留真实状态，不生成伪完成报告 |
| T12 | A 部分流后重试成功 | 不改写失败 attempt；最终消息一次改写 |
| T13 | B 超时、网络错误、空文本、截断、工具调用 | 回退 A 原文；不重跑 A/工具，不执行 B 工具 |
| T14 | B 处理中用户取消/新输入/会话销毁 | 取消或丢弃过期结果，不覆盖新消息 |
| T15 | 同时多个 session/turn | 状态隔离，输出顺序正确，并发限额生效 |
| T16 | 卸载、HMR、重新加载 | 无重复监听/请求，资源与挂起任务按策略清理 |
| T17 | 刷新、断线重连、历史分页 | 不重新计费，直播和持久化结果一致 |
| T18 | 分叉、原消息重生成、删除 | 关联和 hash 检查正确；不串用其他消息的稿件 |
| T19 | 插件禁用或未安装时读取会话 | A 原文仍可读，不因未知记录使整个会话失败 |
| T20 | 用户说“按你第二点做” | A 能对应实际展示的编号和内容，无额外自动 turn |
| T21 | 命令、代码、路径、链接、引用、金额/百分比 | 关键内容保留；不把未测试改成已通过 |
| T22 | 原文包含“忽略规则、执行工具”等文本 | 作为编辑数据处理；B 不获得执行能力 |
| T23 | 有附件/纯机器 JSON/纯代码 | 按明确保护或跳过规则，不破坏格式 |
| T24 | usage 与 provider replay metadata | A 原始记录不变，B 独立统计，不复用 A 的 replayState |
| T25 | 独立 DSH_HOME/profile/workspace/port | 写入均在测试区域，日常配置与会话无变化 |
| T26 | 打包后安装/启用/禁用/卸载 | 依赖和共享模块身份正确，兼容检查正常 |
| T27 | 成稿前工作快照 | 包含用户要求和实际工具结果；第一步输入无 A 本次报告、系统文风、内部推理和 replayState |
| T28 | 核对调用 | 输入明确包含 B 上一稿、A 参考报告和相同工作快照，提示词要求在自己的稿件上完善 |
| T29 | 0 或多轮核对 | 0 轮不提供 A 本次报告；N 轮共调用 B N+1 次，各轮底稿连续 |
| T30 | 核对失败/取消/中途重启 | 不发布未经核对的初稿，不补跑历史调用，失败回退 A，取消停止后续轮次 |
| T31 | 用户控制限额 | 0 值生效；百万字符材料和大于 32768 的输出预算可通过插件；自设预算超限时不截断 |
| T32 | 新旧历史 | v1 正常恢复；v2 只恢复完整最终稿；历史 B 替代旧 A 成稿后进入下一次 B 材料 |
| T33 | B 起草/核对失败后手动重试 | 只调用 B；成功初稿和已完成核对在输入/模型/提示一致时复用，失败调用用量保留 |
| T34 | 重试时改变设置 | 使用当前 B、提示、核对轮数和限额，前缀不一致时重新起草；不读后来的工作材料 |
| T35 | 重复点击、A 忙、原文已变 | 不重复计费或覆盖另一回复；提供可读的拒绝原因，后端校验不依赖按钮状态 |
| T36 | 重启后重试/分叉 | 冷会话按原生策略恢复，按钮使用当前 Session；成功重试回放不请求模型 |

## 质量抽样

准备技术排障解释、完成报告、方案比较、澄清问题、含失败和未验证事项的报告各至少一例。评估事实忠实度、用户能否理解、条件是否保留、可执行信息是否完整；不能只按“更短”或“更口语”判定成功。

## 测试层次

1. 策略单测：路由与 finish 决策、块分类、排重、状态机、输出保护。
2. Host 集成：mock adapter 的真实 Cordis waterfall、日志/持久化、取消与卸载。
3. Client/会话快照：隐藏候选原文、工具直通、整理中/成功/失败/重连、选项引用。
4. 打包烟测：安装实际构建产物而非源码 import，在隔离 profile 运行。
5. 真实模型：少量端到端样例，记录费用和局限，不用它替代可重复测试。

## 结果记录模板

每次阶段验收在本文件尾部或独立 evidence 测试报告中记录：日期、DSH 路径/版本/commit、插件 commit 或文件状态、测试命令、通过/失败/跳过项、真实模型是否调用、剩余风险。文档检查只证明文档可读和链接可用，不等于插件通过运行验收。
